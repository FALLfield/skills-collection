# 英文参考文献核查（对照公开数据库）

你拿到一份参考文献列表（常常来自 ChatGPT / 其他 AI，也可能是学生自己抄录的），要逐条判断它是否真实存在，并指出字段对不对。

**目标使用者：** 以引用英文期刊或会议论文为主的理工、医学研究生和本科生。以中文文献为主的人不是目标客户。本技能不支持知网、万方；对中文条目，公开库找不到时只标「查无此文」，不能确认它是假的。

「对照公开数据库判断文献是否存在」并不稀缺。本包提供的是买断、不限次数、不按积分扣的对照流程，不是独家能力。

## 硬规则

- 查不到时**严禁编造**一条「看起来正确」的替代文献，也不得把相近文章改写成用户应当引用的新条目。
- 可以展示数据库里的对应记录或相近记录，但必须标明「这是库中记录，不是替你生成的正确引用」。
- 「查无此文」或「疑似编造」都不等于最终宣判。中文期刊、书籍、学位论文、新刊、未收录会议论文经常不在 Crossref / OpenAlex 里。
- 不支持知网、万方等需授权的中文商业文献库，也不要假装已经查过它们。
- 脚本和网页会把题名、DOI、PMID 发送到 Crossref、OpenAlex、Europe PMC 查询；只向这些公开学术数据库发送题名或标识符，**不上传全文、不上传整篇稿件**。不要把稿件发到其他商业核查网站。
- 不要把测试计数写成「准确率」。对外应写：在预先标注的 100 条样例上的结果：第 1 批与标签一致 74/100、不一致 26/100；第 2 批（未见过）96/100；第 3 批（未见过）93/100；第 4 批（未见过）95/100；第 5 批（未见过）98/100；第 6 批（未见过）95/100；第 7 批（未见过，跨格式）89/100（其中 6 条为接口失败）。七批都没有达到「100 篇无差错」，因此不能写「零差错」。这只是各批样例上的结果，不是准确率。公开曝光的问题条目在各批中均未被放行成「已验证」。中文条目覆盖有限（不支持知网、万方）。官方 20 条在修完 U/V/W/X 后、第 7 批开跑前与标签一致 20/20（其中 5 条为自造或改错对照；第 19 条允许「查无此文」或「信息部分不符」）。复现步骤见 `tests/REPRODUCE.md`，逐条对照见各批次目录中的 `compare.json`，总览图见 `visuals/overview_hundred.png`。
- 文案不要出现「降重 / 过检测 / 绕过」，也不要把标题写成能拦住一切 AI 编造文献。

## 输入

一段参考文献列表，格式可以是 APA、Vancouver、GB/T 7714，或 AI 随口写的带编号列表。可能夹杂 DOI、PMID。

## 你应如何做

1. 把列表拆成单条，解析作者、年份、题名、期刊、卷期、页码、DOI、PMID（解析不准也没关系，完整书目字符串要送给数据库检索）。
2. 按下面顺序查询公开接口（全部免费、无需 API key）。这些请求会把题名或标识符发到对方服务器：
   - 若有 DOI：`https://api.crossref.org/works/{doi}`，Crossref 没有再试 `https://api.openalex.org/works/doi:{doi}`。
   - 若有 PMID：Europe PMC `https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:{pmid} AND SRC:MED&format=json`。
   - 用完整书目（去掉 DOI/PMID，以免把「张冠李戴的 DOI」抬上去）做 Crossref `query.bibliographic`。
   - 用题名或书目做 OpenAlex `search`。
   - 请求间隔至少 0.3–0.4 秒；脚本的 User-Agent 带 `mailto:`。网页版在浏览器里不能修改 User-Agent，改为给 OpenAlex 请求加上 `mailto` 查询参数，并在页面上说明这一点。
3. 判定时注意：
   - 先看 DOI / PMID 解析出的文章题名是否与引用一致。DOI 或 PMID 真实、但指向另一篇文章，必须明确写出来，并给出那一篇的链接。
   - 过滤或降低 `Faculty Opinions recommendation of …`、`Review for …`、`dataset` / `peer-review` 这类抢位记录的优先级。
   - 同名不同年版本（如同一题名的 1999 与 2008 指南）：优先采用与引用 DOI 一致、或年份更接近的那一条。
   - 第一作者对不上，即使其他作者有重叠，也要标「作者不符」。缩写首名应兼容全名：引用写「Vaswani, A.」，库中是「Ashish Vaswani」，不算作者不符。
   - 中英文刊名或常见缩写差异，在 DOI 已经锁定同一篇时，不要标成不符。
   - 输入只有 DOI，或只有指向 DOI 的 URL，且该标识符能解析时：标「已验证」，并展示库中记录。不要把 URL 拆成作者，也不要因为「库中题名 vs 原始 URL」不像就标「疑似编造」。
   - 必须区分「各库都正常返回但没有匹配」和「请求失败 / 超时 / HTTP 429」。前者才可以标「查无此文」或「疑似编造」；后者必须标「核查失败/无法下结论」，不能写成「查无此文」。
4. 每条只输出以下状态之一：
   - **已验证**：库中找到对应记录，关键字段一致。仅 DOI 或仅 URL 且能解析时也用这一档，并展示库中记录。
   - **信息部分不符**：找到对应或高度相近的记录，但年份、作者、页码、期刊、DOI、PMID 等有不一致；必须逐项写出「引用是什么、库中是什么」。
   - **查无此文**：各库都正常返回，但没有足够相似的记录。中文条目默认用这一档，并说明覆盖不足、不支持知网和万方、不能确认是假的。
   - **疑似编造**：英文条目信息看起来完整，但完全找不到，或所给 DOI/PMID 指向另一篇完全不同的文章。仍要附「不等于最终宣判」的说明。
   - **核查失败/无法下结论**：请求失败、超时或 HTTP 429 等，接口没有给出正常检索结果。这不是「查无此文」，不能据此下结论。
5. 已验证 / 信息部分不符时，给出可点击的验证链接（优先 `https://doi.org/…`，否则 PubMed 链接）。
6. 输出一份人能看懂的报告（推荐 HTML），不要只丢 JSON。

## 推荐实现

优先运行本目录的脚本，不要临时再写一套逻辑：

```bash
python3 check_refs.py 我的文献.txt -o report.html
```

不想用命令行的人，可以打开同目录的 `ref-check.html`，粘贴列表后点「开始核查」（需联网；浏览器会把题名或 DOI 发给上述公开接口）。

## 不要做的事

- 不要为了让报告「好看」而补全或改写用户没写过的文献。
- 不要声称已经查询知网、万方，或任何需授权的中文商业文献库。
- 不要把「未找到」写成「这就是假文献，可以拿去指控学术不端」。
- 不要宣传「不用注册」或「文献不出本机」：Citely 的检查页也可以不注册打开；本工具查询时会把题名或 DOI 发给公开数据库。
